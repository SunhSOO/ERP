# GAILAB ERP Platform — 화면 디자인 브리프

이 문서는 Claude Design에 그대로 입력하기 위한 자립형 브리프다. 승인된 설계 문서
(`docs/specs/01`, `03`, `06`)에서 화면 설계에 필요한 내용만 추출·재구성했다.

- 대상 제품: GAILAB ERP Platform (LEP)
- 기준 문서: `06_UI_UX_INFORMATION_ARCHITECTURE.md`, `03_MODULE_SPECIFICATIONS.md`, `01_PRODUCT_REQUIREMENTS.md`
- 작성일: 2026-09-07
- 구현 현황: 저장소 기반(WP-PLT-001)만 완료. 화면은 전부 미구현이므로 제약 없이 새로 디자인한다.

## 1. 제품 컨텍스트

프로젝트 수행형 소규모 조직을 위한 자체 호스팅 전사 업무 시스템이다. 고객·영업·계약·
프로젝트·업무·회의·문서·산출물·결재·비용·구매·인사·자산·개발활동을 하나로 연결하고,
그 위에 통제된 AI 비서를 얹는다.

| 항목 | 값 |
|---|---|
| 현재 사용자 | 10명 이하 |
| 최대 사용자 | 30명 |
| 로케일 | ko-KR |
| 시간대 | Asia/Seoul |
| 통화 | KRW (numeric + currency 코드 병기) |
| 배포 | 자체 서버 (사내망 중심) |
| 플랫폼 | 반응형 웹 우선, PWA 지원. 네이티브 앱 없음 |
| 다국어 | 현 단계 미지원. 한국어 단일 |
| 다크 모드 | 우선순위 COULD. 토큰은 처음부터 라이트/다크 양쪽 정의 |

### 해결하려는 문제

정보가 이메일, 메신저, 공유폴더, 개인 PC, 스프레드시트, Git, 캘린더로 흩어져 있다.
프로젝트 최신 상태를 사람에게 물어봐야 하고, 회의 결정이 업무로 이어지지 않으며,
최신 문서와 제출본을 구분하기 어렵다. 화면 설계는 이 단절을 메우는 데 집중한다.

## 2. 디자인 원칙

이 여섯 가지가 모든 화면 판단의 기준이다.

1. **오늘 해야 할 일 우선.** 대시보드와 받은 작업함이 진입점이다. 메뉴를 탐색하지 않아도
   오늘 처리할 항목이 먼저 보여야 한다.
2. **프로젝트 컨텍스트 유지.** 프로젝트 안에서 업무, 회의, 문서, 비용을 오가도 지금 어느
   프로젝트에 있는지 시야에서 사라지지 않는다.
3. **목록보다 행동 가능성.** 각 화면은 다음에 할 행동과, 할 수 없다면 그 차단 사유를
   명시한다. 비활성 버튼을 이유 없이 두지 않는다.
4. **초안은 가볍게, 제출은 엄격하게.** 생성 단계 입력은 최소화하고, 상태 전이 시점에
   완전성을 검사한다. 필수 입력과 제출 시 필수를 시각적으로 구분한다.
5. **자동화의 가시성.** AI와 워크플로우가 무엇을 바꿀지 실행 전에 보여준다.
6. **근거 추적.** 모든 지표, AI 답변, 요약에서 원본 레코드로 이동할 수 있다.

## 3. 사용자 역할

역할에 따라 첫 화면과 좌측 메뉴 구성이 달라진다. 권한이 없는 메뉴는 비활성이 아니라
숨긴다. 빈 메뉴를 노출하지 않는다.

| 역할 | 주 관심사 | 기본 진입 화면 |
|---|---|---|
| 대표·경영진 | 수주 예정, 프로젝트 위험, 미수금, 지출, 계약 만료 | 통합 대시보드 (경영 레이아웃) |
| PM | 프로젝트 건강도, 지연 업무, 산출물 누락, 예산 소진 | 프로젝트 개요 |
| 실무 담당자 | 내 업무, 멘션, 회의, 결재 상신 | 내 업무 |
| 영업 담당자 | 파이프라인, 견적, 계약 갱신 | 영업 파이프라인 |
| 재무·구매 담당자 | 결재 대기, 비용 검토, 발주, 수금 | 결재 받은함 |
| 인사·총무 | 근태 누락, 휴가, 자산 배정 | 인사 대시보드 |
| 시스템 관리자 | 사용자·권한, 감사 로그, 작업 큐, 백업 | 관리자 홈 |
| 외부 협력자 | 허용된 프로젝트의 제한된 업무와 문서만 | 제한된 프로젝트 화면 |

외부 협력자 화면은 만료일이 있고, 허용되지 않은 영역은 존재 자체를 노출하지 않는다.

## 4. 디자인 시스템 토큰

아래 토큰 축을 모두 정의한다. 값은 제안이며 조정 가능하다. 색상만으로 의미를 전달하지
않는다는 규칙은 조정 대상이 아니다.

### 4.1 축

- **spacing**: 4px 기반 스케일. `2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64`
- **typography**: 한글 가독성 우선. 본문 14px, 조밀한 데이터 표 13px, 페이지 제목 20px,
  섹션 제목 16px. 행간은 본문 1.6, 표 1.4. 숫자는 tabular-nums 고정폭
- **semantic colors**: 아래 4.2 참조
- **border / radius**: 라디우스 `4`(입력), `6`(카드), `8`(모달), `999`(배지)
- **elevation**: `0`(평면), `1`(카드), `2`(드로어), `3`(모달), `4`(토스트/팝오버)
- **motion duration**: `120ms`(상태 변화), `200ms`(드로어/모달), `320ms`(페이지 전환).
  `prefers-reduced-motion` 존중
- **breakpoints**: `640`(모바일), `1024`(태블릿), `1280`(데스크톱), `1600`(대형)
- **z-index layers**: 본문 `0`, 고정 헤더 `100`, 드로어 `200`, 모달 `300`,
  팝오버 `400`, 토스트 `500`

### 4.2 시맨틱 색상

의미 기반으로 정의하고, 원시 색상 값을 화면에서 직접 쓰지 않는다.

| 토큰 | 의미 | 사용처 |
|---|---|---|
| `surface` / `surface-raised` / `surface-sunken` | 배경 계층 | 페이지, 카드, 입력 안쪽 |
| `border-subtle` / `border-strong` | 구분선 | 표 행, 입력 테두리 |
| `text-primary` / `text-secondary` / `text-disabled` | 본문 위계 | 값, 레이블, 비활성 |
| `accent` | 주 액션 | 기본 버튼, 활성 탭, 링크 |
| `success` | 정상·완료 | 완료 배지, 성공 토스트 |
| `warning` | 주의·대기 | 대기 배지, 기한 임박 |
| `danger` | 위험·지연·오류 | 지연 배지, 삭제, 오류 |
| `info` | 정보·초안 | 초안 배지, 안내 |
| `neutral` | 비활성·보관 | 보관 배지, 취소 |
| `ai` | AI 생성값 | AI 제안 카드, 자동 입력 필드 테두리 |

`ai` 토큰은 별도로 둔다. AI가 채운 값은 사람이 입력한 값과 시각적으로 구분되어야 한다.

모든 조합은 WCAG AA 대비를 만족해야 한다. 배지는 색상에 더해 **반드시 텍스트를 포함**하고,
필요하면 아이콘을 함께 쓴다.

### 4.3 컴포넌트 인벤토리

기본 컴포넌트:

`Button`, `Input`, `Select`, `DatePicker`, `MoneyInput`, `Badge`, `Avatar`, `Table`,
`DataGrid`, `Card`, `Tabs`, `Drawer`, `Modal`, `Toast`, `Alert`, `EmptyState`, `Skeleton`

ERP 전용 복합 컴포넌트:

- `Timeline` — 활동 피드. 행위자, 시각, 변경 요약, 원본 링크
- `CommentThread` — 댓글, 멘션, 첨부, 답글
- `FileUploader` — 업로드 세션, 검사 진행, 준비 완료 3단계 표시
- `ApprovalStepper` — 결재선 단계, 순차/병렬, 현재 단계, 대결 표시
- `StatusTransitionDialog` — 상태 전이 전용 다이얼로그 (5.4 참조)
- `EntityPicker` — 프로젝트·고객·직원·문서 검색 선택
- `ProjectContextHeader` — 프로젝트 코드, 상태, 건강도, PM, 기간 고정 표시
- `AIProposalCard` — AI 제안값, 근거 링크, 채택/수정/무시

### 5.2 상단바

왼쪽부터: 로고, 전역 검색 겸 명령 팔레트, 빠른 생성 버튼, AI 워크스페이스 열기,
알림 벨, 도움말, 사용자 메뉴.

- 전역 검색은 항상 보이고 `Ctrl+K`로 포커스된다
- 빠른 생성 메뉴: 업무, 회의, 문서, 비용, 고객
- 알림 벨은 미읽음 수를 숫자로 표시한다
- 사용자 메뉴: 프로필, 상태, 로그아웃

### 5.3 좌측 메뉴

- 권한에 따라 항목을 숨긴다
- 즐겨찾기와 최근 항목을 상단에 배치할 수 있다
- 접기 가능. 접었을 때 아이콘만 표시하고 툴팁으로 이름을 준다
- 태블릿 이하에서는 오버레이 드로어로 전환한다

### 5.4 우측 컨텍스트 패널

엔터티 상세에서 필요할 때만 연다. 본문을 밀어내는 방식과 덮는 방식 중 데스크톱은
밀어내기, 태블릿 이하는 덮기를 쓴다. 탭 구성:

활동 타임라인 | 댓글·멘션 | 관련 항목 | AI 도움 | 변경 이력

### 5.6 프로젝트 컨텍스트 탭

프로젝트 상세에 진입하면 아래 탭이 고정된다.

```text
개요 | 업무 | 일정·회의 | 산출물·문서 | 리스크·이슈 | 인력 | 비용·예산 | 계약·고객 | 개발·배포 | 활동
```

모든 하위 화면 상단에 `ProjectContextHeader`가 유지된다. 표시 항목은 프로젝트 코드,
상태, 건강도, PM, 기간이다.

## 6. 화면 패턴

### 6.1 목록 화면

구성 순서: 제목과 생성 버튼 → 상태·KPI 요약 칩 → 검색·필터·저장된 보기 →
보기 전환(표/카드/칸반) → 데이터 영역 → 일괄 작업 바.

규칙:

- 필터 상태를 URL에 반영해 공유 가능하게 한다
- 마지막으로 쓴 보기를 사용자별로 기억한다
- 빈 상태에서 다음 행동을 제시한다
- 데이터 없음과 필터 결과 없음을 다른 문구로 구분한다
- 권한 없는 액션은 숨기거나, 비활성 시 사유를 툴팁으로 준다
- 100행 이상은 가상 스크롤 또는 페이지네이션
- 열 표시 설정과 CSV 내보내기를 제공한다
- 일괄 작업은 선택 개수를 명시하고 실행 전 영향 범위를 보여준다

### 6.2 상세 화면

제목·코드·상태 배지 → 주요 액션과 더보기 → 핵심 필드 요약 → 탭/섹션 →
관련 엔터티 → 활동·댓글 패널 → 변경 이력.

### 6.3 생성·수정 폼

- 짧은 폼은 모달 또는 드로어, 복잡한 폼은 전체 페이지
- 자동 저장은 초안에만 적용하고 저장 시각을 표시한다
- 취소 시 변경 손실을 경고한다
- 서버 검증 오류는 해당 필드와 상단 요약 양쪽에 표시한다
- AI가 채운 값은 `ai` 토큰으로 구분하고 원래 값으로 되돌리는 버튼을 준다

### 6.4 상태 전이 다이얼로그

일반 수정과 분리된 전용 다이얼로그를 쓴다. 표시 항목:

1. 현재 상태 → 변경 후 상태
2. 전이 조건 체크리스트 (충족/미충족을 각각 표시)
3. 영향받는 항목 목록
4. 필수 사유 입력 또는 첨부
5. 알림이 갈 대상
6. 즉시 실행인지 승인이 필요한지

### 6.5 승인 미리보기

AI 또는 워크플로우가 중요한 실행을 하기 전 반드시 거친다. 금전, 계약, 인사, 권한,
외부 발송, 대량 변경이 대상이다. 표시 항목:

- 수행 주체 (사람 / AI / 시스템)
- 변경될 엔터티와 필드, 변경 전후 값
- 외부 발송 대상과 첨부
- 금액·권한 영향
- 근거와 원본 링크
- 되돌릴 수 있는지 여부
- 액션 세 가지: 승인 / 수정 후 승인 / 거절

## 7. 화면 상태 표준

모든 화면에 아래 일곱 상태를 디자인한다. 하나라도 빠지면 미완성으로 본다.

| 상태 | 요구사항 |
|---|---|
| Loading | 실제 레이아웃 형태의 스켈레톤. 전체 화면 스피너 금지 |
| Empty | 데이터 없음과 필터 결과 없음을 구분. 각각 다른 다음 행동 제시 |
| Error | 재시도 버튼과 trace ID 표시. trace ID는 복사 가능 |
| Forbidden | 필요한 권한 이름과 문의 대상을 명시 |
| Stale | 데이터가 갱신되었음을 알리고 비교 또는 새로고침 제공 |
| Offline | 저장 가능 여부를 명시. 불가하면 입력을 잠근다 |
| Partial failure | 일부 위젯·연동만 실패했을 때 전체 페이지를 막지 않는다 |

Partial failure는 대시보드에서 특히 중요하다. 집계 실패 시 마지막 정상 데이터와 함께
경고 및 갱신 시각을 표시한다.

## 8. 상태 배지 어휘

실제 도메인 상태값이다. 배지 텍스트는 한국어로 표기하되 내부 값은 아래와 같다.
색상은 4.2의 시맨틱 토큰에 매핑한다.

| 엔터티 | 상태 흐름 | 예외 상태 |
|---|---|---|
| 프로젝트 | PROPOSED → PLANNING → ACTIVE → ON_HOLD → CLOSING → COMPLETED → ARCHIVED | CANCELLED |
| 업무 | BACKLOG → TODO → IN_PROGRESS → REVIEW → DONE | BLOCKED, CANCELLED |
| 산출물 | PLANNED → DRAFTING → REVIEW_REQUESTED → REVISION_REQUIRED → APPROVED → SUBMITTED → ACCEPTED | WAIVED, REJECTED, CANCELLED |
| 결재 | DRAFT → SUBMITTED → IN_REVIEW → APPROVED → EXECUTED → CLOSED | REJECTED, WITHDRAWN, CANCELLED, APPROVED_BUT_FAILED |
| 사용자 | INVITED → ACTIVE → SUSPENDED → DEACTIVATED | 없음 |
| 직원 | PRE_JOIN → EMPLOYED → LEAVE_OF_ABSENCE → RESIGNED | 없음 |

프로젝트 건강도는 별도 축이다. `GREEN`, `AMBER`, `RED`, `UNKNOWN` 네 값이며 자동
계산값과 PM 수동 판단을 함께 보관한다. 수동으로 바꾼 경우 그 사실과 사유를 표시한다.

`APPROVED_BUT_FAILED`는 승인 후 실행이 실패한 상태다. 성공으로 숨기지 않고 별도
배지와 재처리 액션을 제공한다.

## 11. 대표 화면 상세 스펙

### 11.1 UI-002 통합 대시보드

역할별 기본 레이아웃을 제공하고, 사용자가 위젯 표시 여부와 순서를 바꿀 수 있다.

위젯 목록:

- 오늘 일정 및 회의
- 내 업무 / 지연 업무 / 검토 요청
- 내 결재 대기 및 상신 상태
- 참여 프로젝트 건강도
- 최근 문서와 산출물 검토 대기
- 멘션·알림·공지
- 영업 파이프라인
- 프로젝트별 예산 소진율
- 계약·라이선스·자산 점검 만료
- 서버·GPU·서비스 장애
- AI 일일 브리핑

규칙:

- 모든 수치에서 원본 목록으로 드릴다운한다
- 위젯마다 데이터 갱신 시각을 표시한다
- 집계 실패 시 마지막 정상 데이터와 경고를 함께 보여주고 다른 위젯을 막지 않는다
- 대시보드 전용 계산 규칙을 만들지 않는다. 모든 수치는 소유 모듈의 공식 집계값이다

상단 고정 영역: 프로젝트 코드·명칭, 상태와 건강도 배지, PM·고객·계약,

진행률 및 마일스톤 · 기한 임박 및 지연 업무 · 리스크·이슈 · 산출물 완결률 ·
예산·비용·손익 · 최근 회의와 결정 · 최근 문서 · 개발·배포 상태 · 활동 피드

9. 시간 기록 (기능 활성화 시)
10. 변경 이력

`BLOCKED` 상태는 차단 사유와 해소 담당자를 반드시 표시한다. 완료 전환 시 필수
체크리스트와 검토 조건 충족 여부를 전이 다이얼로그에서 확인시킨다.

### 11.4 UI-408 산출물 현황

행이 산출물, 열이 아래 항목인 조밀한 데이터 표다.

코드·명칭 | 필수 여부 | 담당·검토·승인 | 예정일 | 현재 상태 |
최신 작업 버전 | 승인 버전 | 제출 버전 | 고객 피드백

**버전 세 종류를 한 행에서 구분해 보여주는 것이 이 화면의 핵심이다.**
최신 작업 버전, 승인 버전, 제출 버전이 서로 다를 수 있고 그 불일치가 곧 위험 신호다.

기능: 상태·담당·기한 필터, 누락 점검, 일괄 검토 요청, 프로젝트 템플릿 대비 차이,
제출 패키지 생성.

### 11.5 UI-706 AI 워크스페이스

여섯 영역으로 구성한다.

1. 대화 및 요청 입력
2. 현재 컨텍스트 (프로젝트, 문서, 기간)
3. 근거 자료 (인용과 원본 링크)
4. 실행 계획
5. 도구 실행 및 승인 상태
6. 결과 링크

AI 답변 안에서 아래 다섯 가지를 시각적으로 구분한다. 이것이 화면의 핵심 요구사항이다.

확인된 사실 | 계산·집계 | AI 추론 | 제안 | 실행 예정 또는 완료

"완료"는 실제 API 성공 ID가 있을 때만 표시한다. 승인 후 실행이 실패하면 숨기지 않고
별도 상태로 노출한다.

### 11.6 UI-501 결재 받은함

대기 항목, 위임받은 항목, SLA 지연 항목을 구분한다. 행마다 양식, 신청자, 금액,
프로젝트, 경과 시간, SLA 잔여 시간을 보여준다. 목록에서 바로 승인·반려가 가능하되
금액이나 권한에 영향을 주는 건은 상세로 이동시킨다.

### 11.7 UI-001 로그인

이메일·아이디 로그인, MFA 입력, 비밀번호 재설정 세 단계를 한 흐름으로 디자인한다.
사내망 자체 호스팅 환경이므로 소셜 로그인은 없다. 계정 상태가 `SUSPENDED`이거나
`DEACTIVATED`이면 실패 사유를 노출하지 말고 문의 안내만 준다.

## 12. 전역 검색과 명령 팔레트

### 12.1 전역 검색

- 대상: 고객, 프로젝트, 업무, 계약, 문서, 회의
- `project:광주 status:active` 형태의 제한된 검색 문법 지원
- 최근 검색과 즐겨찾기 표시
- 권한이 적용된 미리보기
- 문서 내 일치 위치 표시
- 자연어 AI 검색으로 전환하는 버튼

결과 행에 표시할 항목: 유형, 제목, 코드, 맥락, 최근 수정, 프로젝트, 보안 등급.

### 12.2 명령 팔레트

키보드 중심 사용자를 위한 명령이다. 권한에 따라 필터링한다.

프로젝트·고객·업무로 이동 | 업무 생성 | 회의 생성 | 문서 업로드 | 비용 신청 |
AI에게 현재 화면 질문

## 13. 반응형과 모바일 범위

1차 모바일 최적화 대상:

대시보드 · 내 업무 확인 및 상태 변경 · 댓글과 멘션 · 일정과 회의 ·
결재 승인 및 반려 · 휴가 신청 · 영수증 촬영 비용 신청 · 자산 QR 조회 · 알림

데스크톱 우선 영역: 견적 편집, 간트, 관리자 설정, 대량 문서 관리.

모바일에서 데스크톱 전용 화면에 접근하면 축소판을 억지로 만들지 말고 데스크톱에서
열라는 안내를 준다.

## 14. 접근성 요구사항

- 의미 있는 HTML 구조를 전제로 디자인한다
- 모든 폼 레이블과 오류 메시지를 연결한다
- 키보드만으로 모든 주요 기능에 접근할 수 있다
- 포커스 이동 경로와 포커스 링을 명확히 그린다
- 모달은 focus trap을 걸고 ESC 동작 정책을 정한다
- 상태 변화는 스크린리더에 안내한다
- 색상 대비를 검증한다. 색상 단독으로 의미를 전달하지 않는다
- 표에 헤더와 정렬 상태를 제공한다
- 애니메이션 감소 설정을 존중한다

---

## 15. 안전장치와 피드백

- 성공 토스트만으로 끝내지 않고 변경된 데이터를 화면에 반영한다
- 삭제와 취소는 영향 범위와 복구 가능성을 함께 보여준다
- 대량 작업은 dry-run 미리보기와 실행 후 결과 보고서를 제공한다
- 외부 발송은 수신자, 제목, 첨부를 미리 보여준다
- 금액 변경은 변경 전후를 나란히 비교한다
- AI 제안은 자동 입력임을 표시하고 원클릭 되돌리기를 준다
- 승인 후 실행 실패를 성공으로 숨기지 않고 별도 상태로 표시한다

---

## 16. 하지 말 것

- 색상만으로 상태를 구분하는 배지
- 사유 없이 비활성화된 버튼
- 데이터 없음과 필터 결과 없음을 같은 문구로 처리
- 전체 화면 무한 스피너
- 권한 없는 사용자에게 빈 메뉴 노출
- 대시보드에만 존재하는 계산 로직
- AI 생성값과 사람 입력값을 같은 스타일로 표시
- 중요 규칙을 UI에서만 강제 (서버 검증이 진짜 방어선이다)
- 실제 고객사명, 직원 이름, 금액을 목업 데이터로 사용

목업 데이터는 가상의 회사명과 이름을 쓴다.

## 17. Claude Design 요청 사항

위 브리프를 기준으로 다음을 만들어 달라.

1. **디자인 토큰 아트보드** 한 장. 4장의 모든 축과 시맨틱 색상을 라이트·다크 양쪽으로
   시각화한다.
2. **컴포넌트 시트** 한 장. 4.3의 기본 컴포넌트와 ERP 전용 복합 컴포넌트를 상태별로
   보여준다. 특히 `Badge`는 8장의 모든 도메인 상태값 예시를 포함한다.
3. **앱 셸 아트보드** 한 장. 5장의 레이아웃을 데스크톱과 태블릿 두 폭으로 그린다.
4. **1차 화면 아홉 장.** 10장의 1차 목록을 각각 한 아트보드로 그린다. 각 화면은 기본
   상태를 그리고, 그중 대시보드와 프로젝트 개요는 partial failure 상태를 추가로 그린다.
5. **화면 상태 시트** 한 장. 7장의 일곱 가지 상태를 목록 화면 하나를 예시로 전부 그린다.

전체 폭은 데스크톱 1280px 기준으로 잡고, 데이터 밀도가 높은 ERP 특성상 여백보다
정보 밀도를 우선한다. 다만 행 높이는 최소 40px을 유지해 클릭 표적을 확보한다.
